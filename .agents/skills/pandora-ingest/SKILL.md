# 摄入 LLM-Wiki

仓库根路径（由 pandora-onboard 确认并更新）：`__未绑定__`

执行前核对该路径与当前 Obsidian 仓库；不一致时先运行 `$pandora-onboard` 重新确认并同步八个技能。下文所有相对路径均从该根目录解析，读写不能越界。

先读根目录 `AGENTS.md`、属性字典和 `90 系统/指南/LLM-Wiki协作规范.md`。所有路径都从仓库根目录解析。**新摄入的唯一来源范围是 `00 收集箱` 与 `30 资源`（含子目录）**；用户给路径时先核对它位于其中，只处理指定范围。只说“摄入收集箱”时盘点 `00 收集箱` 并处理可读取且有长期价值的候选；只说“摄入资源”时盘点 `30 资源`。不得把 `10 项目`、`20 领域`（含目标与心愿）、`40 归档` 或 `50 日志` 的文件直接摄入 Wiki，也不创建 `wiki/projects` 或 `wiki/项目`。用户指向这些目录时，说明边界；项目实践中已沉淀、可复用的知识，应先由用户确认整理为 `30 资源` 中的笔记，再从该资源摄入。不要把“整理收集箱”自动解释成 Wiki 摄入；那是 `$pandora-triage`。用户同时要 PARA 整理与 Wiki 摄入时先整理原件，再以最终符合来源范围的路径建立来源链。

1. 查 `wiki/index.md`、现有 `来源笔记` 和文件名，避免重复。读取指定目录内的原始 Markdown 全文，或非 Markdown 文件在收集箱/资源中的 Markdown 侧记；侧记没有实际内容时不根据标题生成知识。辨别示范笔记，输出继续标 `示范: true`。
2. 先确定原文具体支持的主旨、简短证据位置、适用边界和不确定性。优先摄入已整理的资源；收集箱文件只有在确实可读、值得长期检索且用户明确要摄入时才直接处理。若仍有待分类的项目行动、私人目标或无法确认的用途，不摄入、不归档，保留在收集箱交给 `$pandora-triage`。个人待办、项目进度、目标、心愿、日记流水和未证实想法不因关键词相似而进入 Wiki；Wiki 不能变成第二份行动库。
3. 使用 `90 系统/模板/14 Wiki来源.md` 建立或增量更新 `wiki/sources` 页面。`来源笔记` 必须包含实际读过、目前位于 `00 收集箱` 或 `30 资源` 的 Markdown 笔记双链；`关联PARA` 也只填这两个目录中确有帮助的笔记。保留来源 URL，替换模板摘要，设置日期。仅在内容确实支持时使用 `90 系统/模板/15 Wiki实体.md` 或 `90 系统/模板/16 Wiki概念.md` 建立 `wiki/entities`、`wiki/concepts`；不为了填满分类而造页。Wiki 工作模板只以这三份文件为准，不在 `wiki/` 下另建模板副本。
4. 同名页面已有时增量合并并保留不同来源。相互矛盾时记下两个来源与冲突，不静默覆盖。新建/改名后更新 `wiki/index.md` 对应条目；在 `wiki/log.md` 追加本次写入和来源。先核对 Wiki 页、来源双链和索引可解析，再在源 Markdown 写 `Wiki摄入状态: 已摄入`、实际衍生页的 `Wiki关联` 与 `更新时间`。资料实质更新而 Wiki 尚未复核时，标 `Wiki摄入状态: 待更新`；失败或仅起草但没有可追溯 Wiki 页时，保留 `未摄入` 或原状态，不虚报成功。
5. 来源在 `30 资源` 时原位完整保留：不删减正文、附件或其他属性，不移动、不归档；本技能只补必要的摄入标记、双链和更新时间，保留原有 `状态`。来源在 `00 收集箱` 且摄入成功、没有未解决的分流事项时，按 `$pandora-archive` 的移动与链接检查规则，将源 Markdown（及仍在收集箱的对应原件）移至 `40 归档/收集箱/`，写 `状态: 已归档`、`PARA分类: 归档`、`原始路径`、`原PARA分类`、`归档时间`，保留原文与 `Wiki摄入状态: 已摄入`。只有移动和来源链接都验证成功，才确认归档完成；失败则保留在收集箱且 `状态: 待整理`，已成功创建的 Wiki 可保持 `Wiki摄入状态: 已摄入`，并如实报告未归档。
6. 报告摄入、原位保留、已归档、跳过和未能读取的文件。新摄入和增量摄入只接收收集箱或资源；已归档的收集箱原件仅作为已有 Wiki 页的历史来源，供链接巡检，不从归档位置再次摄入。既有 Wiki 页若引用其他目录，仅报告历史来源供复核，不自动删除或改写。
