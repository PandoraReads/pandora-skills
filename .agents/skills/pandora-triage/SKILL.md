# 第二大脑分流

仓库根路径（由 pandora-onboard 确认并更新）：`__未绑定__`

执行前核对该路径与当前 Obsidian 仓库；不一致时先运行 `$pandora-onboard` 重新确认并同步八个技能。下文所有相对路径均从该根目录解析，读写不能越界。

操作前确认仓库根目录并读取根目录 AGENTS.md 和 `90 系统/指南/属性字典.md`。以下路径均相对于仓库根目录。使用已有文件工具，不依赖外部服务。变更后重新读取并验证 YAML、关系目标和目录归属。


1. 只处理用户指定的文件或明确要求整理的 `00 收集箱` 范围。先盘点文件名、格式、现有属性、来源说明与重复项；逐项读取能读取的原始内容，检查已有领域、项目和资源，不只根据标题或关键词分类。原始文字和文件名尽量保留；无法读取的内容标为待阅读，不编造摘要。
2. 判断当前用途：某项目独有的过程、观察或决策记录变为关联该项目的工作笔记；可跨项目复用的资料仍变为 `30 资源` 中的资源，即使它目前支持某个项目，也只用 `关联项目` 建立关系。确有主要领域时再用 `领域` 属性指向领域主页。`20 领域` 根目录保留领域主页，`目标` 与 `心愿` 分别放在现有子目录；不要把一般参考材料直接扔进 `20 领域`。发现新项目、新领域、年度目标或心愿时标为待规划，并交给 `$pandora-plan` 让用户确认，不在分类时替用户建立承诺。不明确的继续留在收集箱。
3. 发现单步行动时，在对应项目行动清单追加一个任务，先查重；收件本身保留原文，变为相关工作笔记，并链接任务所属项目，不复制第二份待办。
4. Markdown 补齐适用属性后再分流；移动与属性同步：现有项目的工作笔记 → `10 项目/项目名/` 且 `PARA分类: 项目`、`关联项目` 指向该目录的项目主页；可复用的领域相关材料 → `30 资源` 且 `PARA分类: 资源`、`领域` 指向已有领域主页。分流完成的原收件写 `状态: 已整理`；资源尚无 Wiki 页时写 `Wiki摄入状态: 未摄入`。移到项目等不允许新摄入的目录时，不保留没有意义的 `未摄入` 默认值；已有 `已摄入` 或 `待更新` 属于历史来源，应保留并复核双链。新领域主页、目标卡和心愿卡只由 `$pandora-plan` 在 `20 领域` 对应目录建立。不再活跃但需要保留的内容列为归档候选，由 `$pandora-archive` 处理移动。类型/状态遵守属性字典，按实际用途更新 `摘要`；没有依据的归属继续留在收集箱，保持 `状态: 待整理`。
5. PDF、图片、音视频、Office 等不能直接写 YAML 的文件，由 Markdown 侧记承载 `摘要`、`类型`、`PARA分类`、`状态`、适用的 `Wiki摄入状态`、`来源`、`关联项目` 与日期，并链接原件；只在确实读到内容时概括。归属明确后原件可放入 `99 附件` 的相应子目录，侧记放入对应 PARA 目录；归属未明时两者仍留在收集箱。查重并避免覆盖已有侧记。
6. 项目关联用双链列表；归入项目的工作笔记核对 `年份`、`年度页` 与项目主页一致，跨年项目先确认这条记录的实际年度。领域指向已存在领域。共享资源仅保留一份，可关联多个项目；若实质改写了已摄入资源而尚未同步 Wiki，写 `Wiki摄入状态: 待更新`。新项目与新领域由 `$pandora-plan` 处理，不在收件分类时虚构验收结果、维持标准或下一步承诺。
7. 用户已经说“整理”时直接完成明确可逆分流；含义不确定的保留原文，并列一个具体问题，不阻塞其余条目。
8. 记录移动前后路径、字段与理由到 `90 系统/日志`；核对附件与侧记链接、PARA/目录一致性、YAML、双链和预期视图。报告已处理、保留待澄清、没有改动的重复项。再次执行不得产生重复项目、任务或资源。

## 与 LLM-Wiki 协作

PARA 分流不自动摄入 Wiki。若收件已有 `Wiki关联`，移动时检查 Wiki 的 `来源笔记` 仍可解析；若最终落入项目、领域、归档或日志，则把该 Wiki 页标记为历史来源待复核，不再从新位置继续摄入。用户要求两层都整理时，先完成本流程；只有最终仍在 `00 收集箱` 或 `30 资源` 的资料才交给 `$pandora-ingest`。
