# 第二大脑统一规划

执行前核对该路径与当前 Obsidian 仓库；不一致时先运行 `$pandora-onboard` 重新确认并同步八个技能。下文所有相对路径均从该根目录解析，读写不能越界。

先读根目录 `AGENTS.md` 和 `90 系统/指南/属性字典.md`。第一步确定用户这次要处理什么：**个人陈述/终身愿景与中期规划、领域、年度页/年度目标与里程碑、项目、心愿、习惯，还是周/年度复盘？** 用户尚未说明时，先用当前环境可用的提问方式让用户选一项；已经明确说出的，不重复询问。一次只进入一个分支，不替用户决定个人承诺。

上表的 references 是本技能的具体操作规则；按所选分支读取即可。`$pandora-review` 是独立技能，复盘请求交由它处理。

个人规划请求默认按这条脉络推进：**个人陈述 / 终身使命 → 3–5 年中期目标 → 年度目标 → 里程碑**。个人陈述、使命和中期目标不单独建文档，写在对应年度索引页顶部的“愿景与中期方向”章节；每次制定年度目标时都先回顾并更新该章节，再检查年度目标对长期方向的承接。上一年度页面保留历史版本。用户只想处理其中一层时，不强行展开全套；用户尚未想清楚时先访谈、总结并请用户修订，不替用户决定人生方向。中期目标用于连接长期愿景和年度行动，不自动等同于单个项目；年度目标依旧使用现有目标卡和年度页。该章节属于正文内容，不新增属性字段；用户确认后按年度模板写入，年度目标和里程碑仍按现有模板创建并互相链接。

若用户要同时处理多个事项，先确认顺序，再逐项读取对应规则；年度规划通常先有年度页，再连接目标与里程碑，项目与目标的关系按实际情况建立。完成后核对属性、目标链接和文件夹；工作台显示与筛选由用户自行维护。需要查询知识库中的历史资料时可用 `$pandora-query`，但不能把 Wiki 的推断写成用户已经确认的承诺。
