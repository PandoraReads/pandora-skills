# 第二大脑归档恢复

仓库根路径（由 pandora-onboard 确认并更新）：`__未绑定__`

执行前核对该路径与当前 Obsidian 仓库；不一致时先运行 `$pandora-onboard` 重新确认并同步八个技能。下文所有相对路径均从该根目录解析，读写不能越界。

操作前确认仓库根目录并读取根目录 AGENTS.md 和 `90 系统/指南/属性字典.md`。以下路径均相对于仓库根目录。使用已有文件工具，不依赖外部服务。变更后重新读取并验证 YAML、关系目标和目录归属。


1. 明确用户指定的项目或笔记。仅要求“找候选”时只列候选，不移动。明确归档某项目时无需重复请求许可，但不扩大到其他项目。`$pandora-ingest` 成功处理的收集箱来源按已约定流程归档；其余收件不能仅因留在 Inbox 就自动归档。
2. 读取主页、专属笔记、被引用资源与所有未完成任务。记录实际结果与证据，未完成任务明确转移、取消或保留；没有证据不把任务勾成完成。
3. 共享 资源 原地保留，即使只剩归档项目引用也不自动归档。可复用的新知识单独提炼，保留出处。项目主页和明确专属笔记按原子批次移动到 `40 归档/项目/项目名`；跨项目笔记不得因同目录就错误随项目归档。
4. 每个移动文件在 `90 系统/日志` 记录原路径、原 `PARA分类` 和原 `状态`；归档页写 `原始路径`、`原PARA分类`、`PARA分类: 归档`、`状态: 已归档`、`归档时间` 为当天，保留类型、创建时间、年份/年度页、领域、关联项目、Wiki摄入状态、Wiki关联及相关笔记，并保留原封面。项目及专属笔记移到 `40 归档/项目/项目名/`，资源移到 `40 归档/资源/`；由 `$pandora-ingest` 成功处理的原收件移到 `40 归档/收集箱/`。资源被摄入 Wiki 后必须原位完整保留，不因摄入而进入归档。
5. 移动前检查重名冲突和受影响引用；有 Obsidian API 使用其重命名/移动方法。否则维护路径映射，更新正文、YAML、嵌入和 工作台路径引用。保留唯一文件名，避免无必要重命名。
6. 恢复时读取 `原始路径`、`原PARA分类` 和归档日志中的原状态，并检查目标没有同名文件；有冲突不得覆盖。恢复相关文件至明确原位置，按记录恢复原状态或由用户指定新状态，不擅自默认成“计划中”；移除仅用于当前归档位置的属性，历史记录保留在日志中。
7. 复查所有关系可解析、文件夹与 PARA分类 一致、归档从活跃视图退出并进入归档视图。中途失败先报告成功与失败文件，不重复归档或无条件整体回滚覆盖新修改。日志保留足够信息以恢复。

## 与 LLM-Wiki 协作

归档只处理明确指定的 PARA 笔记及 `$pandora-ingest` 成功处理的收集箱来源，不顺带移动 `wiki/`。归档后复查 Wiki 的 `来源笔记`、PARA 的 `Wiki关联` 与正文链接；原文仍是权威来源，必要时标记 Wiki 结论待复核。
