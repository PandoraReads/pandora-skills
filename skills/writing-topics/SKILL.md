# 写作选题（需求挖掘 → 灵感博物馆）

**目标：**主动关心用户**正在讨论什么、抱怨什么**；关键词要覆盖工作流、AI 技能、外语学习工具等丰富方向，但每条都必须能**射回**我们的产品或 IP（LME / 第二大脑 / 潘多拉数字花园 / Apex 工作流）。每一条热点 / 现象 / 选题切口写成**单独一张**灵感卡；禁止汇总进一个大 Markdown。

**仓库路径约定：**下文中的 `{{你的仓库}}` 表示你的 Obsidian 仓库根目录。使用前请把该占位符替换为实际路径；不要写入其他人电脑上的绝对路径。

## 落盘位置（强制）

| 用途 | 路径 |
|------|------|
| 灵感卡（每条一文件） | `{{你的仓库}}/00_inbox/08-idea-museum/` |
| 本地下载的封面/配图 | `{{你的仓库}}/00_inbox/08-idea-museum/assets/` |

- **一题一文件**：每一个选题、热点或现象 = 一张**图片**，或一份 **Markdown 笔记**；不得把多条灵感写进同一日「选题库大文件」。
- **禁止**再默认生成 `{{你的仓库}}/00-选题库/YYYY-MM-DD-选题库.md` 这类汇总日报作为本 skill 主产出。
- 流水线 `{{你的仓库}}/00-选题库/` idea 卡由晋升步骤另写；本 skill **默认只写博物馆**。

## 每日定量与质检

- **定量**：每次定时/扫活默认产出 **至少 10 张**合格灵感卡（一题一文件）。材料极缺时可先交已合格张数，但必须在回报里写明缺口并**自动补搜一轮**；仍不足 10 则标「未达标」，不得用假评论凑数。
- **合格标准**（缺任一则该卡作废、须返工）：
  1. 可核对公开出处（或授权脱敏材料）
  2. 标题含【分类】前缀（见下）
  3. Markdown 非空 `封面`
  4. 摘录下方有可点击的**原文超链接**
  5. 正文含简短「射回产品/IP」分析（为何值得我们做）
- **返工**：自检或 Pip/Rae 指出质量不行时，删改不合格卡、补搜、优化本 skill 真源后再交；禁止「明知不合格仍交差」。

## 卡片分类（标题一眼可辨）

文件名与 frontmatter `"标题"` **必须以【分类】开头**，分类从下列选用（可扩展，但要短、一眼懂）：

| 标签 | 何时用 |
|------|--------|
| 【抱怨】 | 明确吐槽、踩坑、崩溃、后悔 |
| 【痛点】 | 反复出现的难受点（未必在骂产品，但是持续卡点） |
| 【未满足的需求】 | 想要却得不到的功能/方法/工具 |
| 【爽点】 | 用户感到畅快、被解决、愿意安利的时刻 |
| 【买点】 | 愿付费/已付费理由、转化触发（功能、信任、场景） |
| 【热点】 | 正在发酵的现象或话题，带讨论热度 |
| 【提问】 | 真诚求教、怎么做 |
| 【对比纠结】 | A vs B、要不要换工具 |
| 【成功窍门】 | 用户分享的可复用做法（可转教程向） |
| 【新产品】 | 高赞/高评论的**用户真心产品分享**（非广告软广）；写清产品名、为何被夸、可射回我们的哪条产品线或差异化观察 |

示例标题：`【抱怨】建成第二大脑仓库后大半笔记从未打开`

## 封面规则

Markdown 灵感卡 **必须** 带封面字段，且封面必须是**能看见画面的图**（工作台灵感页靠它出图）：

- 字段名：`封面`（可写成 `"封面"`）
- **优先顺序（强制）**：
  1. 从原文页抓取可见图并下载到 `assets/`，封面写本地 wiki：`[[00_inbox/08-idea-museum/assets/文件名.jpg]]`
  2. 下载失败 / 站点拦下载 → **直接把页面里那张图的公网 URL** 填进 `封面`（优先 `og:image` / Twitter card 图 / 正文首图 / 用户头图；必须是 `https://…` 图片地址，浏览器打开能出图）
  3. 页面确实无图 → 再用同主题**已成功抓到的真实截图**（非占位），并在回报注明「无页图·复用真实截图」
- **禁止**：用默认黑图、1×1/纯色占位、站点 favicon、通用 `cover-*.png` 模板图、与原文无关的假图充数。占位图 ≠ 合格封面。
- 本地下载只放 `assets/`；缺封面或封面打不开画面 = 不合格，须返工。

## 原文链接（强制）

在正文「用户在讨论 / 抱怨什么」摘录**下面**，单独一行可点击 Markdown 链接，例如：

```markdown
[查看原文](https://example.com/path)
```

禁止只把 URL 塞进 frontmatter 却不在摘录下展示；frontmatter `"来源"` 可与链接一致。

## 主输入（主动出击）

选题 agent **必须自己去公开平台搜集**，不得以「请用户粘贴评论」为一等依赖。

### 强制检索工具：agent-reach（不可跳过）

每次扫活 / 灵感采集 **必须** 先 Load / 使用 **agent-reach** skill，再用它搜读公开讨论；禁止整轮只靠通用网页搜索凑卡。

- 开场先说一句「用 agent-reach skill（X 渠道）」，再按渠道动作检索。
- 优先覆盖本 skill 默认阵地：`xiaohongshu`、`bilibili`、`twitter`/`x`、`reddit`、`v2ex`、`web` 等（`agent-reach channels` 看最新动作与参数）。
- 典型用法：
  - `agent-reach <渠道> search "关键词" --limit 5`
  - `agent-reach read <链接>`
- 自带网页搜索仅作旁证或 agent-reach 失败后的补缺；**主检索必须走 agent-reach**。
- 某渠道 `NEED_LOGIN` / `PLATFORM_BLOCKED` / 不可用：保留已拿到的公开结果，换其他已通渠道补搜，并在回报里写明失败渠道；不得因此改回「等人粘贴」。
- agent-reach 装在共享电脑（box）：`agent-reach` CLI + skill `~/.agents/skills/agent-reach/`；不可用时停止并回报，禁止假装已用。

## 开工前

0. 读 `{{你的仓库}}/00-IP与品牌/品牌记忆-当前口径.md`。  
1. 确认 `{{你的仓库}}/00_inbox/08-idea-museum/` 与 `{{你的仓库}}/00_inbox/08-idea-museum/assets/` 存在。  
2. 规划本轮 ≥4 簇 + 自拓检索词 ≥5 个，避免全挤在 Obsidian，也避免只复读表内原词。

## Workflow

1. **主动搜集（必须经 agent-reach）** ≥3 阵地 × ≥4 关键词簇（含自拓词）；回报注明用了哪些 agent-reach 渠道。  
2. **分级**：客户直接表达 / 公开需求信号 / 推测性线索（待验证）。  
3. **过滤**：与可交付产品/IP 无关 → 丢弃。  
4. **一题一卡落盘**，目标 **≥10** 张合格卡：
   - 文件名：`【分类】短主题-YYYY-MM-DDTHH-mm-ss-<短id>.md`
   - 标题、封面、摘录下原文链接、射回分析齐备
5. **自检**：张数、分类标签、封面、原文链接、射回字段；不合格返工。  
6. **回报**：文件名清单、分类分布、阵地、关键词簇、**本轮自拓检索词**、是否满 10；未达标原因。

- 路径不可写：停止并说明，不要写到其他仓库或未知目录
