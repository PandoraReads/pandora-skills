# 小红书信息图套图

出卡引擎是 [guizang-social-card-skill](https://github.com/op7418/guizang-social-card-skill)（HTML 模板 + 本机 Playwright `node scripts/render.mjs`）。本 skill 管「出图前想清楚什么、何时停下给用户选、怎么验收」。

使用前把 `{{你的仓库}}` 和 `{{你的IP名}}` 换成你自己的仓库根目录和 IP 角色名。

## 0. 读入
1. 定稿卡片默认在 `{{你的仓库}}/内容创作/01-草稿/`（`status: draft`）。你给出其他文件时以该文件为准。读 frontmatter：`标题`、`封面主标题`、`封面副标题`、`配图需求`，以及正文。只用正文和封面字段，不依赖写手的「配图建议」。
2. 读品牌规范 `{{你的仓库}}/assets/brand.md`（颜色、字体）。缺失或无法确定时停下问你，不编。
3. 读 `{{你的IP名}}` 的形象库：`{{你的仓库}}/assets/IP形象/`。先读角色身份锁和 design.md，再列出全部动作贴纸。没有 IP 库时跳过 IP 相关要求。

## 1. 拆文案（必做，写成一张页表）
- **封面钩子**：一句最戳读者的冲突或结论，通常用 `封面主标题`；判断它是痛点、反常识，还是结果承诺。
- **中间要点**：从正文提炼 4～7 个要点，每个要点只承载一个观点。每页要写出：这一页的「一眼重点」（≤12 字，用最大字号或色块突出）、支撑信息（数字、对比、步骤、句式）、版式（对比 / 清单 / 步骤 / 句式填空 / 数据大字）。
- **收束**：一句行动号召或金句，加互动引导。
- 页表每页还要标一个 IP 动作，按页面情绪匹配贴纸：疑惑、思考、讲解、重点提示、恍然大悟、答对了、举手提问、加油打气、鼓掌认可、完成收工、欢迎等。同一套图不得只用一个站姿，至少用 3 种不同动作；封面和收束页必用。
- 数据、产品口径和引用必须与正文一致，不新增事实。

## 2. 三款风格样图（停一闸，等用户选）
1. 根据文案调性挑 3 种明显不同的风格（例：品牌插画手账风、Swiss 大字对比风、杂志编辑风）。颜色和字体都在 `{{你的仓库}}/assets/brand.md` 范围内变化，不另编品牌色。
2. 每种风格只渲染 1 张样图：用封面，或最能代表全套的要点页。三张用同一页内容，方便对比。
3. 把 3 张样图发给你，每张附一句风格说明，问选哪款（可以混搭）。**未选定前不跑全套。**

### 2.1 固定可选风格：小红书大字报
你指定或文案适合一句话冲击时，可作为 3 款样图之一，也可整套使用。
- **构图**：纯色底（或极淡的纯色变体，见下），左上角一对大号双引号「“」，颜色取底色的深一档或浅一档，半透明；下面一句话大字，左对齐，3～5 行，字重最粗；右下角一小段短色条做收尾点缀。
- **字号与重心**：字号不定死，按字数灵活调整（字少可大、字多要小），关键是守住宽度比例：文字整体（最长一行）约占画布宽度 55%～65%，别撑满也别缩成一小块。参考值：1080×1440 画布上 4 行、每行 3～4 个汉字时约 140px。引号固定在左上角顶部（约距顶 40px 起）不动；文字整段紧跟引号下方、整体靠上（第一行约从 320px 起），下方留白交给右下角小色条，不要把文字往画面中间或底部压。
- **高亮**：只给 1 个关键词（偶尔 2 个）加高亮色条，色条压在字的下半部（约字高 35%～50%），其余字全部深灰黑。
- **每次必换（硬规定）**：同一风格每次出图，底色、底的样式、高亮色条的颜色、色条的样式这四项至少换掉三项，不能和上一次一样。
  - 底色：在 brand.md 范围内轮换浅色系，如薄荷绿、米白、浅杏、淡蓝、浅粉、淡紫、浅黄。
  - 底的样式：纯色、极淡纸纹、极淡网格、极淡圆点、上下两色分区、细边框。
  - 色条颜色：与底色形成对比（如绿底配橙黄、米白配荧光绿、淡蓝配珊瑚粉）。
  - 色条样式：平直色块、手绘马克笔笔触、圆角胶囊、双层错位、下划波浪、斜切色块。
- **防重复**：出图前读本目录 `bigtype-history.md`，出完把本次「日期｜卡片 slug｜底色｜底样式｜色条色｜色条样式」追加一行；对比最近 3 次，避免重复组合。
- 一套多张时，每张同一底系但可换高亮色或色条样式，保持整套统一又不单调；IP 要求见第 1 节，可放在右下或贴着关键词。

### 2.2 固定可选风格：白底清单笔记（杂志清单风）
适合「我得到的 N 件事」「N 个 XX」这类个人清单、复盘、经验罗列，读起来像一页私人笔记。可作为 3 款样图之一，也可整套使用。
- **底与色**：纯白或极淡暖白底，不加纹理；文字全部近黑（品牌深色或更深的灰黑），全页只用两种淡色做衬：标题用浅灰衬条，重点条目用很淡的高亮衬底，不出现第三种强调色。
- **封面**：顶部约 15% 处一条细灰横线；下面是 2 行超大标题，宋体（衬线）最粗一档，左对齐，每行宽度约占画布 85%～90%，第一行可带英文或数字；每行标题下压一条浅灰衬条（约字高下 1/3）。标题下方直接开始清单前几条，让读者一眼看到「这是一份清单」。
- **清单**：序号「1. 2. 3.」加一句话，衬线常规字重，字号约为标题的 1/3，行距宽松（约 1.8～2 倍），左对齐、不加图标、不加卡片框。允许「6.5」这种插号，保留手写清单的随意感。
- **重点条**：每页挑 2～3 条最戳人的加粗并铺淡色衬底（压在文字下半部或整行浅底，可带一条细下划线），其余条目保持常规字重；重点条要和文案里的情绪高点一致，不是平均分配。
- **内页**：不再放大标题，清单从页顶接着往下排，序号延续上一页；最后一条可以是一句「没说完但就这样吧」式的收尾，留一点空行表现语气。
- **IP**：只放 1 个小贴纸在右下或贴着某个重点条（指着、举着），尺寸小于画面宽度 20%，不压字；整套仍按第 1 节至少 3 种动作。
- **每次轮换（硬规定）**：版式固定不变，但每次出这款要换重点衬色或衬底形式，不能和上一次一样：衬色在浅黄、浅杏、浅薄荷、浅雾蓝、浅粉里轮换（都要很淡，文字仍是近黑）；衬底形式在「下半截色块＋细下划线」「整行浅底」「马克笔斜扫」里轮换；标题衬条保持浅灰。出图前读同目录 `bigtype-history.md` 里本款的记录（色条样式一栏写衬底形式，卡片 slug 前加「清单｜」），出完追加一行。
- **与密度规则的关系**：这款允许每页底部留少量空行表现呼吸感，但文字仍要盖住画布约 75% 高度，不能出现半页空白；条目不够就加大行距或字号，不要硬塞新内容。

## 3. 密度与重点（每张必守）
- 内容（文字 + 图形 + IP）覆盖画布高度 ≥75%。任何 >15% 画布高度的纯空白带都要改：放大重点字、加色块或图形、放大 IP，或把要点拆细。
- 每页只有一个视觉焦点：一眼重点用最大字号或高亮色块，次要信息降级。不要每行同字号。
- 字少但不空：每页正文 ≤60 字，同时用图标、编号、对比框、句式框把版面撑满。
- IP 贴纸占画面 15%～30%，与内容有互动（指向重点、举牌、站在色块旁），不当角落装饰。

## 4. 全套渲染与自检
1. 按选定风格渲染 6～9 张（第 1 张是封面）。
2. 跑 `validate-social-deck.mjs` 和 qa-checklist 的 4 横带密度检查；逐张打开 PNG 目视，确认无大块空白、重点突出、动作不重复、文案与正文一致。
3. 不过关就改了再渲染，不交半成品。

## 5. 写回与交接
- 图片存到 `{{你的仓库}}/assets/xhs-images/<slug>/01.png…`。配图不跟卡片走：卡片会在 `00-选题库`、`01-草稿`、`02-待发布`、`03-已发布`、`88-已归档` 之间移动，图片留在 `assets/`，链接才不会断。
- 卡片字段写仓库内完整路径，不写会随卡片目录失效的短路径。`封面` 为 `{{你的仓库}}/assets/xhs-images/<slug>/01.png`；`配图` 按顺序写 `{{你的仓库}}/assets/xhs-images/<slug>/01.png` 到同目录的 `02.png`…`NN.png`。不写 `封面图`；不动 `封面主标题`、`封面副标题`、正文。
- 卡片移到 `{{你的仓库}}/内容创作/02-待发布/`，`status` 改为 `review`。若卡片同时有 `状态` 字段，改为 `等待中`。交给发布环节。不代替你点发布。
