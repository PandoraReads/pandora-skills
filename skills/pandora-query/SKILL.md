# 跨层查询

仓库根路径（由 pandora-onboard 确认并更新）：`__未绑定__`

执行前核对该路径与当前 Obsidian 仓库；不一致时先运行 `$pandora-onboard` 重新确认并同步八个技能。下文所有相对路径均从该根目录解析，读写不能越界。

先读根目录 `AGENTS.md` 与 `90 系统/指南/LLM-Wiki协作规范.md`。本技能回答仓库中的记录，不靠模型记忆猜测用户事实。普通通用知识问题无需强制读取整个仓库。

1. 知识观点类问题从 `wiki/index.md` 找候选来源、实体和概念，读取 Wiki 页及其 `来源笔记` 指向的 PARA 原文。索引无匹配或可能过时时，用 `rg` 搜 PARA 的标题、属性和正文；不用仅凭摘要下结论。
2. 项目相关问题始终直接检查仓库根目录 `10 项目/项目名/项目名.md` 和同目录工作笔记，并按需沿项目的 `领域`、`关联目标`、`年度页` 查看 `20 领域` 与 `50 日志/年度`，再检查 `30 资源` 中通过 `关联项目` 指向它的共享资料。不能只因 Wiki 索引有匹配就跳过项目原文，也不要去 `wiki/projects` 或 `wiki/项目` 找项目主页。项目状态、目标、日期、行动和用户原话以 PARA 原文及实际属性为准；Wiki 仅帮助定位与综合。碰到来源冲突、过时状态或示范笔记，明确标出。不要把 `示范: true` 当作 用户的个人事实。
3. 用可定位的 Obsidian 双链引用关键结论，必要时同时引用 Wiki 页和 PARA 原文；说明哪些是原文记录、Wiki 整理或本次推断。两层都找不到时直接说明“本仓库未找到依据”，如需补充通用知识则明确另起说明。
4. 查询默认不写文件、不追加日志。用户明确要求保存高价值综合时，优先创建/更新用户可读的 PARA 资源笔记；若修改了已摄入资源的实质内容而暂未同步 Wiki，写 `Wiki摄入状态: 待更新`。若要求让 AI 后续检索，再用 `$pandora-ingest` 编译或增量更新对应 Wiki 页面，验证来源链后改回 `已摄入`。
