# 年度目标拆解

读取 `AGENTS.md`、属性字典、年度页和目标/里程碑模板。用户需要确认年度、结果方向、主要 领域 和投入边界。将一项目标如何拆解的初稿先呈现给用户确认；确认后再写入。

1. 使用用户指定年份；查重 `50 日志/年度/YYYY.md`。存在时更新为年度导航索引，不重复创建。不存在时从 `90 系统/模板/13 年度.md` 创建。
2. 目标应描述一年期可验收结果，不是持续责任、项目行动或习惯打卡。与至少一个已确认的领域建立 `领域` 双链关联；找不到主要领域时先请用户选择，或进入 `$pandora-plan` 的领域分支建立。
3. 每个确认目标使用 `90 系统/模板/10 目标.md`，文件放在 `20 领域/目标`。写 `类型: 目标`、`PARA分类: 领域`、`年份` 数值、`年度页: "[[YYYY]]"`、领域双链及 `里程碑` 双链列表。不要保留模板中的 0 进度作为实际成果；新目标进度由用户决定或使用 0 并说明它是起始基线。
4. 拆出能验证结果的阶段成果，每项使用 `90 系统/模板/12 里程碑.md` 建在同一个 `20 领域/目标` 子目录。其 `所属目标` 单链指回目标，年份/年度页和领域 与父目标一致。没有用户提供的日期时，`目标日期` 留空；不把季度示例日期当承诺。
5. 将目标和里程碑链接加入年度页的对应章节，核对 `年份`、`年度页`、`领域`、`里程碑` 与 `所属目标`；工作台的显示与筛选由用户自行维护，不把筛选限制写进工作台 Markdown 正文。
6. 检查目标和里程碑双向属性一致、关系目标存在、YAML 类型正确、PARA分类与文件夹一致。批量新建记入 `90 系统/日志`，汇报待用户确认项。

示范笔记带 `示范:true`；从真实用户目标创建时不得继承该字段。

## 与 LLM-Wiki 协作

可以用 `$pandora-query` 查历史目标与相关知识作讨论材料；Wiki 摘要不能替用户确认年度承诺、进度或日期。目标与里程碑仍只写 PARA，确有相关 Wiki 页面时填模板的 `Wiki关联`。
