# 项目计划与推进

先读 `AGENTS.md`、属性字典和项目模板，查找同一成果是否已有项目。长期责任用 领域，年度结果用 目标；不得为同一成果重复建项目。

1. 与用户确认 验收结果（如何验收）、主要领域、投入边界和最小下一步行动。未获用户确认前只起草，不写成承诺。
2. 新项目用 `90 系统/模板/02 项目.md` 建立唯一 `项目-主题.md` 主页和同名目录 `10 项目/项目-主题/`。新建前检查唯一文件名/路径；项目主页同时是 Apex 项目管理卡，不额外创建第二份项目卡。从项目管理分区的新建入口创建时，也要检查新文件是否在同名项目目录、是否具备模板要求的 PARA 属性与年度关系，缺失时补齐，不复制主页。
3. 属性使用 `类型: 项目`、`PARA分类: 项目`、`type: project`、与 `状态` 一致的 `stage`、用户确认的 `领域` 双链，并保留模板的 `年份` 与 `年度页` 关联当前模板年度。`intro`、`nextStep`、`deliverables` 分别与 `摘要`、`下一步行动`、`验收结果` 同步；若确实服务某个年度目标，`关联目标` 写为双链列表并在 目标 的 `关联项目` 中同步；不确定时空着。日期、优先级、状态只依据用户决定。
4. 项目主页承载验收结果、决策、下一步行动和唯一 Markdown 任务清单；待办放在 `## 待办`，只有真实的阶段验收才放在 `## 里程碑`。已有或用户确认的新任务如有确定日期，在同一条任务末尾加 `[due:: YYYY-MM-DD]`；Apex 日历读取这一标记，项目属性 `截止日期` 不会自动变成日历任务。无日期任务不伪造日期，也不另复制任务。工作记录用 `05 工作笔记.md` 放在同一项目目录，并设置 `关联项目: ["[[项目主页唯一文件名]]"]`；`领域`、数值 `年份` 与 `年度页` 应与项目主页一致，跨年项目则先确认记录实际所属年度。通过项目管理分区新建工作笔记时，检查其保存位置和项目关系，不能把未关联的根目录笔记误当成项目成员。
5. 近期行动四象限便签是跳转导航；任务仍只在项目主页或项目工作笔记中保留一个可勾选来源。需要定位行动时为 Markdown 任务添加 Obsidian block ID，并让对应象限便签链接至该任务。不要再复制出一份勾选框。
6. 项目资料通过 `关联项目` 属性连接。共享资源留在 `30 资源` 且可链接多个项目。项目管理分区读取 `type: project` 的主页，并从同名项目目录呈现项目文件；不要将专属工作笔记留在根目录或建副本来满足视图。
7. 推进项目时只记录用户确认或可观察产物支持的事实；达到验收后才可设 已完成。移动、归档按 `pandora-archive`。完成后核对链接、folder/PARA分类、`stage` 与 `状态`、项目管理卡和唯一待办源。

## 与 LLM-Wiki 协作

规划前可用 `$pandora-query` 检索相关资料与既往决策；项目主页与工作笔记的唯一位置仍是仓库根目录的 `10 项目/项目名/`，不在 `wiki/` 内建立项目副本。项目事实、承诺与唯一任务源仍留在 PARA。仅将实际支持项目的 Wiki 页面填入 `Wiki关联`，不从 Wiki 摘要直接生成已确认任务。
