# 领域 设定与复核

先读根目录 `AGENTS.md`、属性字典与 `90 系统/模板/03 领域.md`，并查找当前 领域 笔记。示范 `示范:true` 不代表 用户的真实责任。

新建或重设时，使用一问一答引导用户说明：哪些责任会长期存在、最低维持标准是什么、多久复核、当下有哪些确认的目标/项目。展示候选名称后让用户确认合并、拆分、改名、暂停或建立；不要因为 PARA 需要占位而自动生成通用人生领域。

1. 领域 是没有自然结束日期的持续责任；有可验收结果和结束条件的事项应建项目，年度成果期望应建 目标，不能把二者塞进 领域。
2. 用简短可观察的 `维持标准` 描述“维持良好”的样子。`复核周期` 记录用户选择的频率，`复核日期` 只写用户确认的下一复核日。
3. `维护状态` 只允许 `稳定`、`需关注`、`超负荷`。仅在用户直接陈述或明确复盘证据支持时更新；若没有证据则不设置或保留旧值。
4. 建领域时查重，按 `90 系统/模板/03 领域.md` 建在 `20 领域`，设置 `类型: 领域`、`PARA分类: 领域`。领域是长期索引，不强制写单一年份；只填写确认过的维护状态、复核周期、复核日期与相关笔记。年度目标和项目以各自的 `领域` 属性指回本页，Obsidian 反向链接可查看这些关系。
5. 可在 领域 中列出现有项目/目标链接供导航，但关系主数据留在项目/目标的 `领域` 属性，不重复维护同步名单。
6. 保存后检查 YAML、状态/路径一致、关系目标类型与 主页的 领域 分区。批量合并或重命名时记录路径映射、引用检查和结果到当日日志。

回顾时询问维持标准是否满足、负荷是否合适、哪些承诺需开始/停止/调整。用户未回答的部分保持未知；不要根据项目逾期或打卡缺失给健康领域贴标签。

## 与 LLM-Wiki 协作

若需从历史资料识别候选领域，可先用 `$pandora-query` 检索 PARA 与 Wiki 的证据；Wiki 的推断不等于用户承认的长期责任。领域原件仍只写入 PARA。
