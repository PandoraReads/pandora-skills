# pandora-dankoe-reading：深度阅读与知识应用

基于 Dan Koe 的阅读与输出思路，将阅读组织成「带着问题读 → 不看原文回忆 → 核对与整理 → 实际应用」的循环。用户可以只选择其中一步，无需每次完成全部流程。

## 开始前

1. 确认阅读材料及其来源：用户提供的正文、笔记、PDF 或链接。只分析实际读到的内容；无法读取时请用户提供文本，不猜测作者观点。
2. 确认用户想做预分析、主动回忆、智能笔记、知识复习，还是完整流程。用户已说明时直接开始。
3. 如需写入笔记，先确认目标仓库和适用的笔记模板、目录及属性规则。只在用户指定的仓库内写入；不沿用示范仓库的目录名。
4. 区分作者原意、用户自己的理解和 AI 的建议。引用原文时保留可定位的来源。

## 一、阅读前：预分析

先提取阅读线索，让用户带着问题阅读：

- 作者要回答什么问题？核心论点是什么？
- 哪些论据、例子或限定条件支撑这个论点？
- 哪些术语、前提或反对观点需要特别留意？
- 如果文章给出行动建议，它们适用的场景是什么？

输出简短的论点摘要和 2–4 个阅读问题。预分析是阅读假设，后续应允许用户用原文修正。用户想保存时，再按目标仓库规则创建预分析笔记，并链接原文；不要为每次阅读强制新建文件。

## 二、阅读后：主动回忆

请用户暂时不看原文，先说出或写下：

1. 记住的 3–5 个核心观点。
2. 作者的独特框架或例子。
3. 最意外、最赞同或最质疑的地方及原因。
4. 一个可能的应用场景。

等待用户回答后，再与原文核对。反馈分为「准确记住」「遗漏或误解」「用户的独立发现」三部分。不要把 AI 的预分析当作标准答案；以原文为准。用户希望保存时，按目标仓库规则保存回忆记录并关联来源。

## 三、整理智能笔记

以用户回忆、核对后的原文和个人应用为输入，形成简洁的学习笔记：

- 来源：标题、作者、链接或原文笔记。
- 核心观点：通常 3–5 条，每条注明是作者观点还是用户解释。
- 证据与疑问：关键段落的位置、尚未解决的问题。
- 知识连接：只链接确实存在且相关的概念或笔记。
- 应用：写成具体建议；只有用户确认承担的行动才成为可勾选任务。
- 复习：记录用户实际约定的日期，不凭空设置提醒或完成状态。

需要写入 Obsidian 时，使用该仓库现有模板与属性字段。若接入《潘多拉的数字花园·第二大脑》，人可读的阅读笔记放在合适的 PARA 目录；不要直接把智能笔记写入 `wiki/`。需要 AI 检索层时，先整理为合规资源，再交由 `pandora-ingest` 摄入，并保留来源链。项目行动只保留一个可勾选源，不在阅读笔记和项目卡中重复待办。

## 四、持续学习循环

### 每周回顾

只检查用户提供或目标仓库中实际存在的学习笔记：

1. 本周读了什么，哪些观点仍能不看原文讲清楚？
2. 哪些概念仍模糊，值得重新阅读或提问？
3. 哪些观点能用于当前项目、创作或生活？
4. 已约定的行动完成了吗？结果和理解有何变化？

用已有回顾模板和字段保存结果；不凭标签推断任务已完成，也不自动创建日历提醒。

### 三种加深学习的方法

- **教师法**：围绕一个概念逐题提问，等待用户回答，指出理解准确处与盲区，最后总结复习重点。
- **连接器法**：检查概念之间的支持、对立、类比或跨领域应用；标明已被资料支持的连接与待验证猜想。
- **创造者法**：把理解转成文章、视频提纲、练习题或讲解；为用户的亲身经验和立场留出编辑空间。

详细提问示例见 [AI 学习技巧参考](references/ai_learning_techniques.md)。这三种方法可单独使用，也可按「教师法 → 连接器法 → 创造者法」组合。

## 不同材料的处理

- **文章和博客**：按单篇处理；材料较短时可合并预分析与回忆结果。
- **书籍和长篇 PDF**：按章节处理，再做全书综合；不假设已读完整本书。
- **视频和播客**：先取得可核对的文字稿；无法获取时请用户提供，不伪造引述。

## 完成标准

说明已处理的材料范围、用户回忆与原文之间的差异、形成的见解或应用，以及实际创建或更新的笔记路径。未写入仓库时，直接给出可复制的笔记草稿，不声称已经保存。
